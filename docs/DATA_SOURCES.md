Every dataset, its exact endpoint, when the endpoint was last confirmed, and
whether it has actually been fetched by this code.

## COT — CFTC Traders in Financial Futures, Futures Only

**Endpoint (Socrata Open Data API):**

```
GET https://publicreporting.cftc.gov/resource/gpe5-46if.json
```

**Resource id:** `gpe5-46if` · **Confirmed:** 2026-08-27

The brief pointed at `publicreportinghub.cftc.gov/.../gpe5-46if/explore`, which
is reachable and serves a valid `*.cftc.gov` certificate — almost certainly the
newer browsing UI for the same dataset. CFTC's own Explanatory Notes page links
to `publicreporting.cftc.gov` as the API host, and independent OpenAPI
documentation describes `/resource/gpe5-46if.json` there. The client tries both
hosts in order (`CFTC_API_BASE_URL_CANDIDATES`) and raises only if both fail.

**Status: never fetched by this code.** The build sandbox blocks all outbound
traffic (`403 host_not_allowed`, confirmed by direct `curl`). First live call
will be on your machine. Run `scripts/validate_date.py` immediately afterwards.

### Columns consumed

| Purpose | Column |
|---|---|
| Report date | `report_date_as_yyyy_mm_dd` |
| Contract | `market_and_exchange_names` |
| Open interest | `open_interest_all` |
| Dealer | `dealer_positions_long_all` / `dealer_positions_short_all` |
| Asset Manager | `asset_mgr_positions_long` / `asset_mgr_positions_short` |
| Leveraged Funds | `lev_money_positions_long` / `lev_money_positions_short` |
| Other Reportables | `other_rept_positions_long` / `other_rept_positions_short` |
| Reportable totals | `tot_rept_positions_long_all` / `tot_rept_positions_short` |

Non-reportables are **derived** as `open_interest − Σ(reportable)`, matching
CFTC's own definition, rather than read from a separate field.

If any expected column is missing, the client raises `CftcSchemaError` naming
exactly which ones — it never guesses a replacement or silently produces zeros.
This is the "Data source schema changed" behaviour the brief required (§34).

### Contract names

Configured in `config.settings.CFTC_MARKET_NAMES`, e.g.
`EURO FX - CHICAGO MERCANTILE EXCHANGE`. If a name matches zero rows, the client
raises with a message pointing at the live dataset — because CFTC occasionally
renames contracts, and a contract can also drop out of the report entirely when
fewer than 20 large traders hold reportable positions.

### Known publication gap

COT publication was suspended during the Oct–Nov 2025 lapse in federal
appropriations; the backlog was cleared on a compressed schedule (CFTC press
releases 9138-25, 9147-25). Report dates ≈2025-09-23 to 2025-12-30 were not
released on their normal Friday. Rows in that window carry an explicit warning
rather than a confidently-wrong `availability_date`. See `docs/METHODOLOGY.md`.

## Price — FRED (Federal Reserve H.10 Foreign Exchange Rates)

```
GET https://fred.stlouisfed.org/graph/fredgraph.csv?id={series_id}
```

No API key required. **Confirmed:** 2026-08-27. **Status: never fetched by this
code**, same sandbox restriction.

| Currency | Pair | FRED series | FRED's published unit | Convention |
|---|---|---|---|---|
| EUR | EURUSD | `DEXUSEU` | USD per 1 EUR | base |
| GBP | GBPUSD | `DEXUSUK` | USD per 1 GBP | base |
| AUD | AUDUSD | `DEXUSAL` | USD per 1 AUD | base |
| JPY | USDJPY | `DEXJPUS` | JPY per 1 USD | quote |
| CAD | USDCAD | `DEXCAUS` | CAD per 1 USD | quote |
| CHF | USDCHF | `DEXSZUS` | CHF per 1 USD | quote |
| MXN | USDMXN | `DEXMXUS` | MXN per 1 USD | quote |
| **NZD** | NZDUSD | **none** | — | base |

Each series was selected because its published unit definition already matches
the market convention used in `FX_PAIRS`, so no inversion is applied.

FRED uses `.` for missing observations; those rows are dropped, not
forward-filled.

### NZD has no source

FRED publishes no standard NZD/USD daily series. Rather than invent a plausible
series id, `fetch_price_series("NZD", …)` raises `PriceSourceNotConfigured` with
instructions. Wire in an alternative (RBNZ, or a commercial feed) if you need
it. Until then NZD COT analysis works; NZD price, forward-return and regime
features do not — a per-currency degradation, not a platform failure (§57).

## Synthetic demo data

Generated by `src/data/synthetic.py`, tagged `source="synthetic_demo"` on every
row, and surfaced as a red **DEMO MODE** banner in the UI and dashboard.

It exists because the build sandbox has no network access, so the only way to
exercise the full pipeline for real was to generate data shaped like the real
thing. It deliberately injects a small, documented positioning→price effect
(`ENGINEERED_SIGNAL_COEF = 0.35`, one-week lag) so that
`scripts/run_demo.py` can check the statistics machinery actually recovers a
known effect.

**Recovering that effect is evidence the code works. It is not evidence about
FX markets.** Never export or present this data as real.

## Source transparency

Every row in `cot_raw` and `price_raw` stores `source` and `ingested_at`.
Derived tables are always rebuildable from those. If a source is unreachable,
the platform raises a clear error — it never substitutes placeholder or
randomised values for missing real data.
