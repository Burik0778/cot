## 1. Исправлено

**Дата за границей pandas.** `date(2999,1,1)` в тесте роняла pandas 2.x
(`OutOfBoundsDatetime`, потолок `datetime64[ns]` — 2262-04-11). Но
настоящая проблема была не в тесте: **та же конверсия стояла в боевом
коде защиты от заглядывания в будущее**. На pandas 2.x защита падала с
невнятной ошибкой вместо честного отказа — то есть на части сред
механизм фактически не работал. Сравнение дат переведено на объекты
`date`, добавлено 4 регрессионных теста, включая дату за границей.

**Захардкоженное число тестов.** «132 tests — all pass» разошлось с
действительностью. Добавлен `scripts/count_tests.py --update-readme`,
README обновляется скриптом.

**Событийный анализ.** Отрицательные горизонты обращались к
несуществующим колонкам и молча возвращали NaN — предсобытийной части не
было вовсе, хотя интерфейс показывал её как готовую. Переписан: −8/−4/−2/−1
считаются по прошедшей цене, точка 0 равна нулю по определению.

**Порог событий в процентах.** «Движение 5%» для евро давало 1 срабатывание
против 106 несрабатываний — евро столько не ходит. Порог теперь
перцентильный от собственного распределения инструмента и показывается в
пунктах.

**Уровни вместо событий.** «Фонды у нижней границы» — состояние, оно
длится месяцами и ничего не запускает. Признаки заменены на изменения:
всплеск потока, перелом через ноль, схлопывание расхождения.

## 3. Главный результат прохода

Сайт раньше показывал по евро **+10 п.п. преимущества** на горизонте 8
недель. С честным учётом зависимости наблюдений:

| | значение |
|---|---|
| Сырых наблюдений | 37 |
| Без перекрытия | 5 |
| Эффективный размер | 5 |
| Блочный ДИ доли | [24%, 57%] |
| Базовая ставка | 50% |
| **Вывод** | **преимущество НЕ доказано** |

Прежняя цифра была артефактом подсчёта перекрывающихся наблюдений как
независимых. Это не регресс качества — это исчезновение результата,
которого не было.

Режим «Только COT» дал −6.9 п.п., «COT + цена» −4.5 п.п. На
синтетических данных; на ваших числа будут свои, но метод тот же.

## 7. Известные риски

Порядок по опасности:

1. **Данные не сверены с CFTC.** Всё остальное стоит на этом. Первое, что нужно сделать.
2. **Названия контрактов и метрик угаданы по документации.** Если рынок не подтянется, в логе сборки будет список похожих названий из живых данных.
3. **Эффективный размер выборки мал почти везде.** Это свойство задачи, а не дефект: недельные данные с многонедельными горизонтами дают мало независимых наблюдений. Отсюда честный вывод «не доказано» вместо красивых цифр.
4. **Оценка эффективного размера как n/h — приближение.** Консервативное; точнее была бы поправка на автокорреляцию.
5. **Синтетические данные не рынок.** Все числа в этом отчёте получены на них.

## 9. Как проверять гипотезу

Кратко; подробно — `docs/RESEARCH_PROTOCOL.md`.

1. Сформулируйте гипотезу до просмотра данных
2. Зафиксируйте условие целиком: участник, метрика, порог, горизонт
3. Вкладка «Проверка» — обратный взгляд: что было перед крупными движениями
4. Вкладка «Доказательства» — эффективный размер, а не сырой
5. Интервал накрывает базовую ставку — преимущество не подтверждено
6. Считайте свои проверки: каждая — ещё один шанс на случайность
